## 메뉴 구성

좌측 메뉴는 **세 그룹**입니다. 대시보드 타일은 **한 줄 6개**(홍보센터 5 + 파트너사)이며
계정 관리는 타일로 두지 않습니다 — 콘텐츠 현황이 아니라 운영 설정입니다.

| 좌측 메뉴 그룹 | 항목 | 성격 |
|---|---|---|
| **홍보센터** | 공지사항 · 언론보도 · 홍보영상 · 갤러리 · 발행물 | 게시물 (기획서 slide 105) |
| **사이트 콘텐츠** | 파트너사 | 사업주체 페이지와 메인 푸터에 들어가는 내용 |
| **설정** | 계정 관리 | 운영자 계정 · 권한 |

⚠ **파트너사는 홍보센터가 아닙니다.** 게시물이 아니라 사이트 본문 콘텐츠입니다.
'사이트 콘텐츠' 그룹은 앞으로 관리로 옮길 항목들이 들어갈 자리이기도 합니다 —
구조도 지분율 · 공식문서 목록 · 추진일정 · 권역 면적 · KPI 수치.

기능은 없지만 **버튼을 누르면 해당 화면으로 실제 이동**합니다.

| 누르면 | 가는 곳 |

**파트너사 순서는 실제로 바뀝니다** — 손잡이를 끌거나, 손잡이에 초점을 두고
위·아래 화살표를 누르면 됩니다. 옮기면 순서 번호가 다시 매겨집니다(저장은 안 됩니다).
⚠ 드래그만 두면 키보드·터치에서 순서를 못 바꾸므로 화살표 이동을 함께 넣었습니다.

**토글은 실제로 눌립니다** — `<button aria-pressed>` 로 만들어 키보드·스크린리더에서도
상태가 읽힙니다. 다만 값이 저장되지는 않습니다.

필터 칩 · 검색 · 페이지 번호는 **동작하지 않습니다**(화면만).

표 목록은 한 쪽에 **10행**입니다(공지사항 · 언론보도 · 발행물).
홍보영상 · 갤러리는 카드형이라 행 수 대신 카드로 노출됩니다.

- 각 입력 위의 회색 배지(`INPUT` · `TEXT EDITOR` · `FILE UPLOAD` · `TOGGLE` · `RADIO BUTTONS` ·
  `DATE PICKER` · `SELECT` · `MULTI UPLOAD` · `URL INPUT`)는 **기획서 표기를 그대로 옮긴 것**입니다.
  구현할 컨트롤 종류를 그 배지로 판단하시면 됩니다.

- 필드 아래 회색 글씨는 제약(최대 글자수 · 용량 · 개수)입니다.

'협의가 필요합니다' 대신 **권장 값과 이유**를 제시했습니다. 검토 후 확정해 주세요.

| 항목 | 권장 | 이유 |
|---|---|---|
| 비밀번호 정책 | 10자 이상 · 영문 · 숫자 · 특수문자 · 같은 문자 3회 반복 금지 | 비밀번호 변경 화면에 이 규칙으로 구현해 뒀습니다 |

| 감사 로그 | 로그인 · 권한 변경 · 게시물 삭제 | 누가 · 언제 · 무엇을 · 어디서(IP) |

- 비밀번호 해시 저장 · **규칙 서버 재검증**(화면 검사는 개발자 도구로 우회됩니다)

- 2단계 인증 도입 여부
- 감사 로그(누가 언제 무엇을 바꿨는지)

## 개발 쪽에서 결정해야 하는 것

1. **인증** — 정적 호스팅에서는 클라이언트 검증이 소스만 열면 우회됩니다.
   로그인 · 세션 · 권한은 서버에서 처리해야 합니다. 비밀번호 정책 · 로그인 실패 제한 ·
   2단계 인증 도입 여부는 미정입니다.
2. **저장소** — 게시물 본문/이미지/PDF(최대 100MB) 보관 위치. 현재 홈페이지는
   `src/sub/data/*.json` 을 빌드 시점에 정적 HTML 로 굽는 구조입니다(백엔드 없음).
   API 로 바꿀 경우 교체 지점은 `tools/build/pages.mjs` 의 `loadContent()` **한 곳**입니다.
3. **예약 게시** — 지정 시각에 공개로 바꾸는 주체(크론 · 스케줄러)가 필요합니다.
4. **조회수** — 현재 사이트에는 카운터가 없습니다.
5. **파트너사 단일화** — 지금 파트너 정보가 메인 푸터(5개)와 사업주체 페이지 카드(13개)로
   **이원화**돼 있습니다. 이 화면을 단일 출처로 삼으면 두 곳이 자동으로 맞습니다.

## 사람이 적지 않아도 되는 값 — 서버가 채웁니다

운영자가 손으로 넣을 필요가 없는 값은 **입력 칸을 두지 않았습니다.**
아래는 서버가 채워야 하는 것입니다.

| 값 | 어디서 얻나 | 못 얻으면 |
|---|---|---|
| `duration` 재생 시간 | 직접 업로드는 **파일 메타데이터**, YouTube 는 **Data API v3** (`contentDetails.duration`) | 비워 두면 됩니다. 빌더가 값이 없으면 배지를 그리지 않습니다 |
| `date` 등록일 | 저장 시각 | — |
| `id` | 서버 채번. **한 번 정하면 바꾸지 않습니다**(앵커·통계가 물립니다) |  — |

⚠ YouTube 재생 시간은 **API 키가 필요**합니다(oEmbed 로는 안 나옵니다).
  키를 두지 않기로 하면 그 경우만 비워 두거나, 그때만 입력 칸을 되살리면 됩니다.

⚠ **썸네일은 입력 칸을 남겨 두었습니다.** YouTube 는 자동으로 가져올 수 있지만
  (`i.ytimg.com/vi/<id>/maxresdefault.jpg`), 직접 업로드 영상은 첫 프레임이
  대표 그림으로 적절하지 않은 경우가 많고 운영자가 고르고 싶어 합니다.
  자동으로 채우되 **바꿀 수 있게** 하는 편이 낫습니다.

## 비밀번호 재설정 절차

로그인의 `비밀번호를 잊으셨나요?` 는 이 흐름으로 이어집니다.

1. **`password-reset.html`** — 아이디(메일) 입력 → 재설정 링크 발송
2. **`password-reset-sent.html`** — 발송 안내. 링크 유효 **30분**
3. **`password-reset-new.html`** — 새 비밀번호 설정(규칙 검사 동작) → 로그인

⚠ ①의 응답은 **계정이 있든 없든 같아야 합니다.** 다르면 어떤 메일이 관리자 계정인지
알아낼 수 있습니다(계정 열거). 요청 횟수 제한도 필요합니다 — 권장 5분에 3회.
⚠ 재설정 토큰은 **1회용 · 30분 · 사용 후 즉시 폐기**. 만료·재사용 시 안내 화면이 별도로 필요합니다.
⚠ ②의 `링크를 눌렀을 때 화면 보기` 버튼은 **시안 확인용**입니다. 실제로는 메일 링크로만 들어갑니다.

## 파트너사 지분율은 세 가지 상태입니다

| 입력 | 구조도 표시 |
|---|---|
| 숫자 입력 (예: 37.3) | `37.3%` |
| **확정 전** 체크 | `TBD` |
| 숫자도 비우고 체크도 안 함 | 표기하지 않음 |

`확정 전` 을 체크하면 숫자 입력이 잠깁니다 — 두 값이 동시에 채워지면 구조도에
무엇을 넣을지 정해지지 않습니다. **입력칸에 '확정 전' 이라고 적는 것이 아닙니다.**

## 개발자에게 확인이 필요한 내용은 **HTML 주석**입니다

화면 문구는 **운영자가 읽을 기능 설명만** 담습니다. 개발 쪽 확인·협의 사항은
소스의 `<!-- DEV: … -->` 주석으로 넣었습니다 — 브라우저에는 보이지 않고 소스에는 남습니다.

```bash
grep -rn 'DEV:' admin/*.html      # 확인이 필요한 항목만 뽑아 보기
```

현재 5건입니다 — 삭제 정책 · 임시 비밀번호 · 권한 등급 · 권한 집행 · 비밀번호 재검증.
로그인 화면의 보안 권장안 패널만 예외로 화면에 그대로 뒀습니다.

## 빌드할 때마다 자가 점검이 돕니다

`npm run build:admin` 이 끝나면 아래를 검사하고, 걸리면 **exit 1** 로 알립니다.

| 검사 | 왜 |
|---|---|
| 죽은 CSS | 화면에서 안 쓰는 `.ad-*` 규칙 — 손볼 때 헷갈립니다 |
| 정의 없는 클래스 | 마크업에 있는데 CSS 에 없는 클래스 — 조용히 스타일이 빠집니다 |
| 안 쓰는 토큰 | 참조가 사라진 `--ad-*` |
| 화면에 남은 개발자 문구 | 운영자 문구와 섞이는 것을 막습니다 |

실제로 이 점검이 `table()` 미사용 함수 · `.ad-flag`/`.ad-checks` 죽은 CSS ·
게시 상태 필드 6중복을 찾아냈습니다.

## 다시 만들기

```bash
npm run build:admin      # tools/build/admin.mjs → admin/*.html
```

화면 명세는 `tools/build/admin.mjs` 의 `SCREENS`/`pages` 에 모여 있습니다.
스타일은 `src/admin/css/admin.css` 이며, 색 토큰은 사이트 것(`src/sub/css/00-tokens.css`)을
그대로 쓰고 관리자에만 필요한 상태색만 파일 상단 `:root` 에 따로 모았습니다.

⚠ `admin/` 은 `.gitignore` 대상입니다 — **공개 배포에 올라가지 않습니다.**
로그인처럼 보이지만 실제로는 아무것도 막지 않는 화면이 실서비스 도메인에 노출되는 것을
막기 위한 것입니다. 인계는 이 폴더를 그대로 전달하세요.
