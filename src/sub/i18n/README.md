## ⚠ 번역하지 않은 것 · 별도 판단이 필요한 것

- **개인정보처리방침**(`en/index.md` §11) — ✅ **확정(2026-09-15): 번역하지 않는다.**
  「개인정보 보호법」 제30조에 따른 공개 의무 문서이고 조문 번호와 고시 별지 서식을
  인용한다. 영문 페이지에서도 **한국어본을 그대로 노출**하고, **모달 제목 바로 아래**에
  한 줄을 붙인다 —
  `This Privacy Policy is provided in Korean. The Korean version is the governing text.`
  ⚠ 정식 영문본이 필요해지면 **법무 검토를 거친 번역**을 받고, **그때 이 문장을**
  「해석에 다툼이 있으면 한국어본이 우선한다」로 **바꿔야 한다** — 지금 문장은 영문본이
  없다는 전제의 것이다. 용어와 기관 공식 영문명은 `GLOSSARY.md` **§11** 에 고정해 두었다.
- **개인정보 보호책임자 이름**은 원문 그대로 두었다 — 실명이므로 로마자 표기를 임의로
  정하지 않는다(이미 공개된 법정 고지 항목이다).
- **GNB 의 `준비중입니다` 말풍선**은 번역 대상이 아니라 **제거 대상**이다.
  영문 페이지가 생기면 `EN` 이 실제 링크가 된다(«다음 단계» 5번).
- 홍보센터 목록 콘텐츠(`src/sub/data/*.json`)는 **전부 샘플**이라 번역하지 않았다.
  실제 게시물이 확정되면 그때 함께 번역한다.
- 이미지 안에 글자가 박혀 있는 자산은 번역 대상이 아니다 — 교체가 필요한 목록은
  `LAYOUT-NOTES.md` 의 «이미지 · SVG» 에 있다.

### `review-rows.csv` — 2차 검토판 (1,259행 · 13열)

**번역본은 「영어」 한 칸이다.** 1차 CSV 의 `영어(현재)` · `영어(수정안)` 두 칸을 합쳤다 —

⚠ **읽기 어려워서 다섯 칸을 뺐다**(2026-09-14 지시) — `검토 구분` · `우선순위` ·
`PC 컨펌 상태` · `모바일 컨펌 상태` · `재검증 항목`. **정보를 버리지는 않았다**:

| 뺀 칸 | 어디로 갔나 |

| `재검증 항목` 의 「처음 보는 행」 표시 | **`행 유형`** — `번역 문구 · 신규` 처럼 뒤에 「· 신규」가 붙는다 |
| `재검증 항목` 의 확정·주의 안내 | **`메모` 앞머리**에 한 줄로 짧게 (`✅ …확정` · `⚠ …또 바뀔 수 있습니다`) |

## ✅ 국문·영문 강조 일치 — 치환기를 고쳤다 (2026-09-21)

전수 대조에서 **네 자리**가 어긋나 있었다. 둘은 증상이 반대다.

| 자리 | 증상 | 원인 | 조치 |
|---|---|---|---|
| 메인 `#location` 02·03 제목 | 영문에만 **연한 파랑**(`ov-em`) | 사전 셀의 `**` — 국문에는 강조가 없다 | `**` 를 걷었다 |

### ⚠⚠ 치환기 수정 — 조각 수가 달라도 국문 태그를 되쓴다

`i18n.mjs` 의 `compile()` 은 `kb === eb && kr === er`(굵게·`<br>` 개수가 **둘 다** 같을 때)
만 원래 태그를 되쓰고, 아니면 잡은 구간을 통째로 갈며 `<b>`·`<br />` 로 단순화했다.
번역이 국문 줄을 합치거나 강조를 옮기는 자리가 많아 **영문만 강조를 잃었다.**

지금은 캡처를 **종류별 큐**로 갈라 조각 수와 무관하게 되쓴다.

⚠⚠ **순서대로 소비하면 안 된다.** 국문 `[br, br, bold]` 의 캡처는 `3+3+6` 순인데
영문이 `[br, bold]` 면 bold 가 **두 번째 br 의 캡처**를 먹어 태그가 뒤섞인다.
⚠ 영문 조각이 더 많으면 **마지막 태그를 다시 쓴다** — 한 문장에서 하나는 `<em>`,
하나는 `<b>` 가 되는 것보다 낫다. 국문에 그 종류가 **아예 없을 때만** `<b>`·`<br />` 다.
⚠ 텍스트 조각을 **항상 `trim()`** 한다. 태그와 맞닿는 공백은 캡처가 공급하므로
(`pad()`), 원문 공백을 함께 쓰면 두 칸이 된다.

**회귀 검증 — 34쪽을 스냅샷과 전수 비교했다.** 바뀐 것은 의도한 **세 쪽뿐**이고
나머지 31쪽은 한 바이트도 같다. 남은 한국어 259줄 그대로.

```bash
cp -R en /tmp/en-before && npm run build:en
for f in en/*.html; do cmp -s $f /tmp/en-before/$(basename $f) || echo $(basename $f); done
```

### 대조 한 줄 — 앞으로 이걸로 확인한다

```bash
for f in en/*.html; do b=$(basename $f); [ -f "$b" ] || continue
  for t in 'class="ov-em"' '<em[ >]' '<strong[ >]'; do
    a=$(grep -o "$t" $b | wc -l); e=$(grep -o "$t" $f | wc -l)
    [ "$a" = "$e" ] || echo "$b  $t  KO $a / EN $e"; done; done
```

**실측 결과(2026-09-21)** — 34쪽 전부 일치. 렌더 계산색도 1:1 이다:
`company` 11개(프라이머리 4 · `#2185ff` 5 · 회색 2) · `living` 5개(`ov-em` 연한 파랑) ·
`location` 4개(프라이머리 2 + **민트 띠 2** · 민트 1).

⚠ **개수만 맞추는 것이 목적이 아니다.** `location` 은 강조 **위치**가 국문과 다르다
(국문 「1시간 생활권」 · 영문 `global business hub`) — `en/location.md` 가 근거를 적어 둔
**의도된 번역 결정**이다. 개수·색·띠가 같으면 된다.
